# Agent Guidelines — Диск-Мастер (Tauri 2)

Windows 11 desktop app: React 19 + Tailwind 4 in `src/client`, Rust backend in
`src-tauri`, renderer in the system WebView2. No browser target, no Node server.

## Commands

```bash
pnpm dev                 # tauri dev (Vite + Rust)
pnpm build:web           # UI only -> dist/client
pnpm build:portable      # release build -> output/DiskMaster-portable-<ver>/
pnpm build:installer     # NSIS + updater artifacts
pnpm check:types         # tsc
pnpm lint                # eslint
cd src-tauri && cargo test
cd src-tauri && cargo clippy -- -D warnings
```

## Rules

- File naming: lowercase kebab-case (`tab-large-files.tsx`, `build-portable.ts`).
- Never add a local HTTP server or a port. Communication is Tauri IPC only.
- UI talks to Rust through `src/client/api.ts`; the `queryClient` facade there
  mimics the old oRPC helpers, so tab components stay unchanged.
- Shared data contract: `src/shared/types.ts` must match the serde structs in
  `src-tauri/src/types.rs` (`#[serde(rename_all = "camelCase")]`). Change both.
- Any new backend feature is a `#[tauri::command]` in `src-tauri/src/commands.rs`,
  registered in `src-tauri/src/main.rs`, plus a typed wrapper in `api.ts`.
- Long/blocking work goes through `spawn_blocking`; commands are async.
- Destructive operations must validate paths with
  `guard::assert_deletable` (protected system paths, drive/profile roots,
  symlinks, allow-list from scan/analysis results).
- Metrics/processes use `sysinfo`; programs and startup use `winreg`; the recycle
  bin uses `SHQueryRecycleBin`; the scheduler uses `schtasks`. Do not reintroduce
  PowerShell for these paths.
- The elevated helper is a separate binary (`src/helper.rs`). Its operations are
  a fixed allow-list; never accept raw shell commands or arbitrary paths.
- The sensor module is a separate managed host (`sensors/`, net472 x64). It is
  built by `scripts/build-sensors.ts` into `src-tauri/resources/sensors/`
  (gitignored) and launched elevated only on demand. Never install PawnIO
  automatically: the install is a user action with a confirmation and UAC.
- The widget is a second Tauri window (`widget.html`) with Win32 z-order and
  click-through applied from `widget.rs`; it is not a separate process.
- There is no PowerShell dependency anymore. Do not add PowerShell scripts or
  child processes; use native Windows APIs, `sysinfo`, `winreg`, `schtasks`.
- UI strings are wrapped in `t("русский текст")`; add English variants to
  `src/client/i18n-en.ts` and manual fixes to `src/client/i18n.ts`. Locale is
  stored in `localStorage` (`dm.locale`) and pushed to the backend with
  `set_locale` for the tray and notifications.
- Version lives in `package.json`; run `pnpm version:sync` before builds (the
  release/portable scripts already do).
- Updater signatures: never commit `*.key`, `*.sig`, `tauri/target`, `output/`.
  `latest.json` is generated by `scripts/release.ts`.

## Storage

- Installed: `%LOCALAPPDATA%\DiskMasterData` (legacy `DiskMaster` is copied
  once by `paths::migrate_legacy_data`, never deleted).
- Logs: `%LOCALAPPDATA%\DiskMasterData\logspp.log` (append-only).
- Portable: `disk-master-data` next to the exe, enabled by `portable.marker`.
- Use `crate::paths::storage_path` instead of hardcoded paths.

## UI notes

- All 12 tabs are conditional renders in `src/client/app.tsx`.
- Charts are SVG (`sparkline.tsx`); avoid adding heavy chart dependencies.
- Keep the light theme contrast at WCAG AA (≥4.5:1).
